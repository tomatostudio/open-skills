# EB获取激活项目名称技能

## Overview

用于查询Engineering Base客户端中当前用户正在操作的项目名称。作为EB相关MCP操作的前置上下文判断工具，帮助AI助手理解当前工程环境。

## MCP调用规范

### 工具元数据
- **className**: `EBTool`
- **methodName**: `GetActiveProjectName`
- **returnTypeFullName**: `System.String`

### 调用方法
你必须通过YdMcpServer提供的MCP服务中调用call_mcp_tool_func功能来执行此功能，并且传入的类名和方法名称必须与调用规范中的要求保持严格一致，否则你将会得到一个致命的调用错误。

## 核心特性

### 即时查询（无缓存）
- ?? **即时查询结果**：返回当前EB状态的查询结果
- ?? **不会被缓存**：多次调用可能返回不同结果
- ?? **依赖EB进程状态**：要求EB正确实例化且处于活跃状态

### 返回结果说明
1. **正常情况**：返回当前激活项目的名称字符串
2. **异常情况**：
   - EB未实例化：返回状态提示字符串
   - 无激活项目：返回状态提示字符串
   - EB进程异常：返回错误信息

## 使用场景

### 场景1：环境验证
```csharp
// 检查EB当前状态
className: "EBTool"
methodName: "GetActiveProjectName"
// 返回示例："当前激活项目：项目A" 或 "EB未正确实例化"
```

### 场景2：前置条件检查
在执行EB自动化操作前，确认当前操作目标项目。

### 场景3：上下文感知
帮助AI助手理解用户当前在哪个项目中进行操作。

## MCP调用语义说明

### 依赖性
- ?? **依赖EB进程状态**：必须已启动Engineering Base
- ?? **依赖用户操作**：取决于用户在EB UI中激活的项目
- ?? **实时性**：每次调用都是实时查询，不缓存历史结果

### 无副作用
- ? **只读操作**：不修改EB状态
- ? **无对象缓存**：不涉及GUID管理
- ? **纯查询**：不影响用户当前操作

## 验证要点

### 调用验证
1. **必须真实调用**：不能模拟或假设项目名称
2. **className正确**："EBTool"完全匹配
3. **methodName正确**："GetActiveProjectName"完全匹配
4. **无参数调用**：不能传递任何参数

### 结果验证
1. **即时性**：返回当前状态的查询结果
2. **可变性**：不同时间调用可能返回不同结果
3. **状态依赖**：结果取决于EB实际状态

### 与OpenWorkSheet集成
1. 先获取当前激活项目
2. 根据项目名称为OpenWorkSheet操作提供上下文
3. 或验证项目状态后再执行操作

## 错误处理

### 常见错误状态
1. **EB未启动**：返回EB未实例化提示
2. **无激活项目**：用户未选择任何项目
3. **连接错误**：MCP与EB通信失败
4. **权限问题**：无访问当前项目权限

### 处理策略
1. **重试机制**：短暂延迟后重试调用
2. **用户引导**：提示用户检查EB状态
3. **降级处理**：提供替代方案或手动操作指引

## 最佳实践

### 使用时机
1. **开始工作前**：验证EB环境是否就绪
2. **操作切换时**：确认项目上下文变更
3. **错误检查时**：诊断操作失败原因

### 避免模式
1. ? 缓存项目名称（可能过时）
2. ? 假设项目状态（可能已变更）
3. ? 跳过环境检查（可能导致失败）
