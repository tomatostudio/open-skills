# EB打开工作表技能

## Overview

用于控制Engineering Base (Aucotec EB)客户端在当前激活项目中打开指定的工作表。这是典型的MCP驱动UI操作，具有可视化副作用。

## MCP调用规范

### 工具元数据
- **className**: `EBTool`
- **methodName**: `OpenWorkSheet`
- **returnTypeFullName**: `System.String`
- **参数类型**: `System.String`

### 调用方法
你必须通过YdMcpServer提供的MCP服务中调用call_mcp_tool_func功能来执行此功能，并且传入的类名和方法名称必须与调用规范中的要求保持严格一致，否则你将会得到一个致命的调用错误。

### 参数说明
1. **工作表名称**：需要打开的EB工作表名称
   - 默认值：`"器件"`
   - 必须与EB项目中已存在的工作表名称一致

## 核心特性

### UI副作用操作
```csharp
// ⚠️ 具有副作用的操作（Side Effect）
// 实际UI行为发生在EB客户端中
// 用户会看到工作表切换的视觉效果
```

### 视觉反馈机制
- 在EB客户端界面打开指定工作表
- 用户可以直接看到UI视图变更
- MCP服务器仅返回执行状态

### 状态返回
执行结果的可能返回值：
1. `"打开工作表成功"` - 操作成功
2. `"工作表不存在"` - 指定工作表不存在
3. `"EB未实例化"` - EB未启动或连接失败
4. `"项目未激活"` - 当前无激活项目

## MCP调用语义说明

### 副作用特性
- ⚠️ **UI实际交互**：在EB客户端中产生视觉效果
- ⚠️ **不会返回对象引用**：仅返回执行状态
- ⚠️ **不涉及对象缓存**：返回值是字符串状态说明

### 调用要求
1. **前置条件**：EB必须已实例化且有激活项目
2. **工作表存在性**：指定工作表必须在项目中存在
3. **权限验证**：用户必须有权访问该工作表

## 验证要点

### 调用验证
1. **必须真实调用**：不能模拟打开操作
2. **className正确**："EBTool"完全匹配
3. **methodName正确**："OpenWorkSheet"完全匹配
4. **参数类型**：必须是字符串类型

### 副作用验证
1. **UI变化**：EB客户端界面会相应切换
2. **用户感知**：用户可以直接看到视觉效果
3. **状态反馈**：返回字符串状态而非对象

## 错误处理

### 常见错误
1. **工作表不存在**：名称错误或项目不包含该表
2. **EB未启动**：未启动Engineering Base
3. **项目未激活**：用户未选择任何项目
4. **权限不足**：无权限访问该工作表
5. **工作表已锁定**：其他用户正在编辑

### 处理策略
1. **名称检查**：验证工作表名称准确性
2. **状态检查**：先检查EB和项目状态
3. **备用工作表**：尝试打开其他相关工作表
4. **用户提示**：明确告知问题及解决方法

## 最佳实践

### 推荐做法
1. ✅ 先验证项目状态再打开工作表
2. ✅ 使用常见的工作表名称（如"器件"、"材料表"）
3. ✅ 处理所有可能的返回状态
4. ✅ 记录用户常用的工作表名

### 避免做法
1. ❌ 假设工作表一定存在
2. ❌ 忽略前置状态检查
3. ❌ 缓存工作表名（可能因项目不同而异）
4. ❌ 不处理失败情况
